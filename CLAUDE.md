# CLAUDE.md

This file gives Claude Code context when working in this repository (a fork/workspace on top of [LeRobot](https://github.com/huggingface/lerobot)).

## Project context

Dual-arm aerial cable-connector insertion task for a factory scenario, extending a phase-conditioned imitation learning framework (PHASER/T-Mech-style: FiLM-conditioned ACT + force-aware phase predictor + closed-loop failure recovery) to a new 4-phase task:

1. Aerial grasp of a hanging cable + align to docking pose
2. Peg-in-hole insertion
3. Re-grasp closer to the connector (for sufficient insertion force)
4. Forceful final insertion

**Current focus: phase 2 (peg-in-hole insertion) only**, decoupled from the other phases (one arm fixed, holding the connector; the other arm runs the learned policy).

## Base IL model

- Custom model referred to as **FACT** (Force-aware ACT): ACT backbone with a GRU preprocessing block for wrench/force history, force/pose/vision tokens fused via the standard ACT transformer encoder, FiLM-conditioned by phase embedding.
- Trained via behavior cloning on teleoperated demos collected through the LeRobot dataset format.
- Ablation finding (already established, do not re-litigate without discussion): for the isolated peg-in-hole phase, **single-frame force outperformed a 50-step force-history + GRU encoding fed as a policy input token**. Hypotheses: closed-loop re-inference already implicitly encodes history; GRU enlarges the hypothesis space relative to demo count; 50-step window may mismatch actual phase duration. Cross-attention for the force encoder was also evaluated and not recommended (self-attention already allows cross-modal interaction). The GRU force-history idea is being redirected to the **phase/failure predictor** instead of the policy (see below).
- The FACT policy checkpoint is treated as **frozen** for the current work — it is the base policy for residual RL, not something to retrain from scratch.

## Current task: residual SAC warm-up

Building an **off-policy residual RL** layer on top of the frozen FACT policy:

- Final executed action combines `a_IL(s)` (frozen FACT policy) and `a_residual(s)` (SAC actor), **but position/gripper and rotation must be combined differently — see "6D rotation composition" below. Do not naively add the full action vectors.**
- SAC (not PPO, not vanilla Q-learning) — chosen for sample efficiency (off-policy, replay buffer) and because the action space is continuous (dual-arm 6D pose + gripper).
- **SAC implementation**: check this repo for an existing HIL-SERL-style RL implementation (actor/learner split, human-intervention hooks, reward-classifier interface, replay buffer with demo warm-start) before writing SAC from scratch — if present, its human-intervention and reward-classifier interfaces map closely onto our manual-override button and failure predictor, and its actor/learner process split is built for real-robot online RL without blocking the control loop. **Located — see "Residual SAC implementation" below.**
- **Residual actor/critic input**: uses FACT's intermediate features (not raw sensor input), specifically pooled encoder-output tokens (originally: GAP, same pattern used in the phase predictor, flatten/pool the whole token sequence to a single `1×d_model` vector — **superseded, see "FACT feature pooling" below**: plain full-sequence GAP lets the state/wrench tokens (1 each) get drowned out by the ~hundreds of image tokens per camera, exactly the information contact-rich manipulation needs most) rather than the full token sequence. **Must `.detach()` / wrap in `torch.no_grad()`** when pulling these features — FACT must never receive gradients from the SAC loss, this is easy to silently break. If the critic later fails to show meaningful Q-value discrimination between good/bad residual actions, a layer earlier than the final encoder output is a reasonable thing to try (FACT's last-layer features are optimized for direct action regression, not necessarily for preserving fine-grained contact/alignment information).
  - **Decided against, for now (do not re-litigate without discussion)**: (a) bypassing the encoder entirely and feeding SAC the raw pre-encoder tokens (3 cameras × ~60 tokens × 512-dim + pose 512 + wrench 512, unattended) — rejected because it would force SAC to re-learn cross-modal fusion that FACT's encoder already learned, but from a much weaker/noisier training signal (online TD updates on a few hundred transitions/day vs. supervised BC on the demo set) and a much larger, high-dimensional input; (b) adding the (previously policy-rejected) GRU force-history encoding as an extra SAC input token — rejected for now purely to keep scope down: getting the residual-SAC loop working end-to-end is the priority, and stacking two unproven ideas (SAC itself + a new force-history modality) at once would make failures hard to diagnose. Revisit (b) later as a flagged/optional input, A/B'd against the no-GRU baseline, once the base loop is working — not before.
- Twin Q-networks, automatic temperature (entropy coefficient) tuning — do not hand-tune α unless automatic tuning is demonstrably unstable.
- Reward is **terminal-only**: success episodes get `reward = 1` on the final frame, everything else is `0` (this already matches the LeRobot-style dataset convention used for the teleoperated demos — do not invent a denser reward without discussion).
- Discount factor `γ` should be tuned lower than long-horizon defaults (e.g. try 0.9–0.95 first, not 0.99) since episodes are short (single peg-in-hole attempt, on the order of seconds).

### 6D rotation composition (applies everywhere position/rotation actions are combined — read before touching action-space code)

The 6D rotation representation is **not a vector space**: never add/subtract two 6D vectors directly, the result has no valid geometric meaning (re-orthonormalizing via Gram-Schmidt after adding does not correspond to "rotate by A then rotate by B"). Position and the gripper scalar ARE plain vector spaces and can be added/subtracted normally — only the 6D rotation sub-vector needs the special handling below.

- **Forward composition (actor output → executed action)**: convert both the residual actor's 6D rotation output and FACT's 6D rotation output to rotation matrices via the same Gram-Schmidt procedure FACT itself uses, then compose via matrix multiplication: `R_final = R_IL @ R_res` (residual applied in the IL-predicted pose's local frame — matches the physical intuition that insertion alignment error is a small twist about the end-effector's own axis). Confirm this convention matches whatever frame the impedance controller expects before committing to `R_IL @ R_res` vs. `R_res @ R_IL`. Convert `R_final` back to 6D only if something downstream requires that format; the impedance controller can likely take the rotation matrix/quaternion directly.
- **Inverse composition (demo action → residual label, for warm-up)**: do NOT compute the rotation part of `a_residual` by subtraction. Convert `a_demo`'s and `a_IL(s)`'s 6D rotation parts to `R_demo` and `R_IL`, then `R_residual_demo = R_IL⁻¹ @ R_demo` (matrix inverse = transpose), convert back to 6D. Position/gripper residual is still plain subtraction.
- **Actor output-layer initialization gotcha**: zero-initializing the rotation output layer's *weights* is fine, but the *bias* must be initialized to the identity rotation's 6D encoding `[1,0,0,0,1,0]` (two orthogonal unit vectors), not zero — Gram-Schmidt on an all-zero 6D vector normalizes a zero-length vector (NaN). With this bias init, a near-zero weight update still yields `R_res ≈ I`, i.e. a true no-op residual, consistent with the actor-initialization goal below.

### Warm-up plan (what we're implementing right now)

1. **Convert demo transitions to residual-action space.** For every `(s, a_demo)` pair in the existing teleoperated dataset, run the frozen FACT policy to get `a_IL(s)`. Compute the residual per the composition rules above: position/gripper via subtraction, rotation via `R_IL⁻¹ @ R_demo` (not vector subtraction). Store `(s, a_residual, r, s')` tuples — this is what populates the replay buffer, not the raw demo actions.
2. **Critic (Q-network) warm-up**: pretrain the twin Q-networks offline on the converted demo transitions before any real-robot rollout, so the critic isn't giving pure-noise signal on day one. Watch for value overestimation on out-of-distribution residual actions (demo residuals cluster near identity-rotation/zero-translation; twin-Q min should help but isn't a full fix — flag this if Q-values look unstable/divergent during warm-up).
3. **Actor initialization**: do NOT behavior-clone the actor on demo residuals. Zero-initialize (near-zero weights) the residual actor's output layer so it starts as a no-op on top of the IL base policy — translation/gripper: near-zero output is already a no-op; rotation: near-zero weights + identity-encoding bias (see rotation-composition section above), not plain zero. Let the actor learn purely from the (warmed-up) critic during online SAC updates.
4. Keep the frozen FACT policy path and the SAC actor/critic path as clearly separate modules — the FACT checkpoint should never receive gradient updates in this phase of work (see the `.detach()` note above — this is the most likely place to accidentally break that rule).

## Residual SAC implementation (entry points)

- **HIL-SERL stack exists** in this checkout: `src/lerobot/rl/{actor,learner,buffer}.py` (+ gRPC in `lerobot/transport`). Reused as-is: `lerobot.rl.learner` (learner), `ReplayBuffer`, transport, `SACPolicy` losses/target updates/`forward(model=...)`, `MLP`/`CriticEnsemble`, and (via a thin wrapper, see below) `lerobot.rl.actor`'s gRPC plumbing (`learner_service_client`, `receive_policy`, `send_transitions`, `send_interactions`). **Not reusable**: `SACPolicy`'s observation encoders and actor (image/state only, generic init, no rotation handling); the in-repo env/rollout half of `lerobot.rl.actor` and `gym_manipulator.py` (control loop is external, see below); the reward classifier (image-only; manual success/failure labels are used instead).
- **Deployment is external, not this repo's env/gym.** The user's real control loop is a separate ROS2 program (not lerobot), so there is **no in-repo `ResidualRobotEnv` / rollout loop** — that was an earlier design, removed. Instead:
  - `src/lerobot/policies/residual_sac/runner.py` — `ResidualPolicyRunner`: the `FACTPolicy.select_action`-style entry point the ROS2 side calls every control-loop tick. `select_action(observation)` (raw dataset-format obs, unbatched) returns `{"action": (16,) composed a_IL+a_residual ready for the impedance controller, "a_il", "residual", "feature"}`; `reset()` once per episode; `encode_intervention(human_action_16d)` for HIL labels (uses the last call's a_IL, inverse composition — not subtraction); `load_actor_state_dict(...)` to hot-swap actor weights.
  - `src/lerobot/rl/residual/online_client.py` — `ResidualOnlineClient`: the matching piece that reports `(s, a_residual, r, s', done)` transitions back to the (unmodified) learner over gRPC, wrapping `lerobot.rl.actor`'s connection/thread functions so the ROS2 control loop never blocks on the network. `record_transition(...)` buffers a step; `end_episode(stats)` flushes it + pulls updated actor weights into the runner in place. **Gotcha found while testing this**: don't put a `TeleopEvents`-style `Enum` as a `complementary_info` dict *key* — transitions are `torch.save`/`torch.load(weights_only=True)`-pickled over the wire (`lerobot.transport.utils.bytes_to_transitions`), which rejects un-allow-listed Enum keys; `record_transition` stores `is_intervention` as a plain `{"is_intervention": float}` instead. This also means the existing `TeleopEvents.IS_INTERVENTION`-keyed check in (unmodified) `lerobot.rl.learner.process_transitions`, meant to route interventions into the offline buffer, can't actually fire for any transition that went over the wire — a pre-existing gap in the reused code, not something silently patched here.
- Policy `residual_sac` (`ResidualSACConfig` subclasses `SACConfig`, `ResidualSACPolicy` subclasses `SACPolicy`): `src/lerobot/policies/residual_sac/`
  - `residual_action.py` — all action-space math (6D via rotation matrices, `R_res @ R_IL` (world) or `R_IL @ R_res` (local), inverse composition, layouts). Executed action = 16-d `[l_pos3, l_quat4(xyzw), l_grip, r_pos3, r_quat4, r_grip]`; FACT output = 20-d `[l_pos3, l_grip, r_pos3, r_grip, l_rot6d, r_rot6d]` (pos/grip normalised with ACTION stats, rot raw); residual = 10-d per arm `[pos3, grip, rot6d]` (tanh range, identity rot = `[1,0,0,0,1,0]`), or 9-d `[pos3, rot6d]` when `ResidualSACConfig.residual_include_gripper=False` -- for a task where the gripper is fixed (e.g. always closed), it's dropped from the residual space entirely rather than kept as a dimension the actor has to learn to leave near zero; the gripper still executes, just always exactly FACT's own prediction, same as the fixed (non-residual) arm already does. `RES_ROT` is always the *last* 6 entries regardless of which layout is in play, so most code (`ResidualActor`'s bias init, `canonicalize_action`, `warmup_critic.py`'s diagnostics) needed no dimension-specific branching.
  - `fact_backbone.py` — `FrozenFACT`, two entry points: `forward(obs)` (training: `convert_demos.py`/`warmup_critic.py` — always a fresh `predict_action_chunk`, first action of the chunk, **no temporal ensembling**, confirmed fine to differ from deployment) and `select_action(obs)` (deployment: goes through `FACTPolicy.select_action` itself, so it reproduces FACT's own action queue / `temporal_ensemble_coeff` smoothing — used by `ResidualPolicyRunner`).
